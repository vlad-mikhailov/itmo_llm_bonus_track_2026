# Governance 

## Risk Register

| Риск | Вероятность | Влияние | Детект | Защита | Остаточный риск |
|---|---|---|---|---|---|
| Prompt injection через пользовательский ввод | Средняя | Высокое | Guardrail-классификатор на входе | Санитизация ввода, system prompt изолирован, тесты на инъекции в eval | Низкий |
| Галлюцинация фактов о местах | Высокая | Среднее | RAGAS faithfulness < порога → алерт | Ответ строго на основе retrieved контекста, явное указание источника | Средний |
| Неверное распознавание места по фото | Средняя | Среднее | Порог уверенности модели | Агент явно сообщает об уровне уверенности, предлагает подтвердить | Средний |
| Геокодирование даёт неверные координаты | Низкая | Среднее | Проверка координат на разумность (bbox города) | Фильтрация аномальных точек, уведомление пользователя о пропущенных местах | Низкий |
| FAISS возвращает нерелевантный контекст | Средняя | Среднее | Similarity score < threshold | Fallback на Wikipedia API, явное сообщение об ограниченности данных | Низкий |
| Утечка system prompt | Низкая | Среднее | Мониторинг ответов на паттерны инструкций | System prompt не возвращается пользователю, тест на "расскажи свои инструкции" | Низкий |
| Превышение лимитов API (OpenRouter, Weather) | Средняя | Высокое | Мониторинг счётчиков запросов | Rate limiting по user_id, exponential backoff, graceful degradation | Средний |
| Off-topic или нежелательный контент в ответе | Низкая | Высокое | LLM-as-judge postcheck (выборочно) | Guardrail на входе, system prompt с ограничениями тематики | Низкий |
| Падение VPS / контейнера | Средняя | Среднее | Healthcheck + systemd watchdog | Restart policy unless-stopped, systemd автозапуск | Низкий |

## Политика логов

### Что логируется

- Timestamp запроса и ответа
- user_id (хешированный, см. ниже)
- Выбранные инструменты и их результаты (без содержимого сообщений пользователя)
- Тип входящего контента (текст / фото) — без сохранения самого контента
- Latency каждого этапа пайплайна
- Ошибки и исключения с трейсбэком
- Similarity score из FAISS (для мониторинга качества retrieval)
- Результат guardrail-проверки (пропущен / заблокирован)

### Что НЕ логируется

- Текст сообщений пользователя в открытом виде
- Фотографии, отправленные пользователем
- История диалога в логах (хранится отдельно в зашифрованном профиле)
- Какие-либо персональные данные

### Retention

- Логи хранятся 30 дней, затем удаляются автоматически
- Агрегированная статистика (без привязки к пользователю) хранится бессрочно

## Работа с персональными данными

Система не собирает персональные данные в явном виде. Единственный идентификатор — Telegram user_id.

**Анонимизация:** user_id хешируется через SHA-256 перед сохранением в базу. Оригинальный id не хранится нигде, кроме оперативной памяти во время активной сессии.

**Профиль пользователя** содержит только: хешированный id, список тем интереса (выводится из диалога, не собирается явно), краткую историю диалога (последние N сообщений). Пользователь может запросить удаление профиля командой `/forget`.

**Фотографии** не сохраняются — передаются напрямую в multimodal LLM для распознавания и немедленно удаляются из памяти.

**Передача третьим сторонам:** тексты запросов и фото передаются в OpenRouter API (DeepSeek, Gemini) для генерации ответов. Координаты города передаются в OpenWeatherMap API для получения погоды. Пользователь информируется об этом при первом запуске через `/start`.

## Защита от инъекций

### Prompt Injection

На входе каждого запроса запускается классификатор, который детектирует попытки:
- Изменить роль или инструкции системы ("ignore previous instructions", "ты теперь...")
- Извлечь system prompt ("расскажи свои инструкции", "что тебе сказали")
- Переключить тематику на запрещённые области

При детекте — запрос отклоняется с нейтральным сообщением, инцидент логируется.

### Image Injection

При получении фото проверяется что изображение содержит реальную сцену, а не текст с инструкциями (например, фото листа бумаги с командами). Детектируется через отдельный препроцессинг перед передачей в vision-модель.

### Изоляция system prompt

System prompt передаётся только в системном поле API-запроса, никогда не конкатенируется с пользовательским вводом в одну строку.

### Санитизация ввода

Входящий текст очищается от потенциально опасных паттернов перед передачей в пайплайн.

## Подтверждение действий

В текущем PoC агент не совершает необратимых действий — не пишет никуда от имени пользователя, не бронирует, не отправляет данные третьим лицам кроме LLM API и картографических сервисов.

При расширении функциональности (например, добавление бронирования или отправки маршрута на email) — любое действие с внешним эффектом должно запрашивать явное подтверждение пользователя перед исполнением.
