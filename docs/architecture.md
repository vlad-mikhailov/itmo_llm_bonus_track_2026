# Архитектура FinOps AI Gateway

## Обзор

FinOps AI Gateway — это API-шлюз, спроектированный для централизованного управления
запросами финансовых AI-агентов к различным LLM-провайдерам.

## Основные принципы

1. **Единая точка входа** — все агенты обращаются к одному API, а не к провайдерам напрямую
2. **Отказоустойчивость** — circuit breaker и health-aware routing исключают упавших провайдеров
3. **Наблюдаемость** — каждый запрос трейсится, метрики экспортируются в Prometheus
4. **Безопасность** — guardrails фильтруют опасные запросы и утечки данных

## Поток запроса

```
Агент → [Auth Middleware] → [Guardrails] → [Балансировщик] → [Provider] → Ответ
                                                ↓
                                        [Circuit Breaker]
                                        [Health Filter]
                                        [Strategy Select]
```

1. **Auth Middleware** — проверяет Bearer-токен (master или agent)
2. **Guardrails Pipeline** — последовательно проверяет запрос:
   - PromptInjectionGuardrail — regex-паттерны инъекций
   - SecretLeakGuardrail — утечки ключей/паролей
   - FinancialPIIGuardrail — номера карт (Luhn), счета, СНИЛС
3. **Model Router** — конвейер выбора провайдера:
   - Health filter — убирает unhealthy провайдеров
   - Circuit breaker — убирает провайдеров с накопленными ошибками
   - Strategy — применяет выбранную стратегию (latency / cost / round-robin / weighted)
4. **OpenRouterClient** — проксирует запрос к выбранному провайдеру с поддержкой streaming
5. **Телеметрия** — записывает метрики TTFT, TPOT, duration, tokens, cost

## Стратегии балансировки

| Стратегия     | Алгоритм                                  | Когда использовать              |
|---------------|-------------------------------------------|---------------------------------|
| Round Robin   | Циклический перебор                       | Равные провайдеры               |
| Weighted      | Случайный выбор по весам                  | Приоритизация конкретного       |
| Latency-based | EMA задержек, выбор минимума              | Оптимизация скорости            |
| Cost-aware    | Выбор по минимальной цене за токен        | Оптимизация расходов            |

## Circuit Breaker

Три состояния:
- **CLOSED** — нормальная работа, ошибки считаются в скользящем окне
- **OPEN** — провайдер отключён (≥5 ошибок за 60 сек), кулдаун 30 сек
- **HALF-OPEN** — пропускается один пробный запрос для проверки

## Деплой

Все компоненты разворачиваются через Docker Compose:
- `app` — FastAPI gateway
- `prometheus` — сбор метрик
- `grafana` — дашборды
- `langfuse` + `langfuse-db` — LLM-трейсинг
- `market-analyst` — агент-аналитик (опционально)
- `risk-assessor` — агент оценки рисков (опционально)
